# Hussam Yassen — personal brand website

Astro 5 + TypeScript, static HTML, Arabic (default RTL), English and Portuguese. Current release: 9 page types × 3 locales = 27 localized pages, plus root Arabic redirect. No CMS or deployment is included. Public canonical origin is configured as `https://husamyasen.com` in `astro.config.mjs` and `src/config/site.ts`. The domain is not connected by this source package.

## Local setup

Use Node.js **22 LTS** (Node 20.3+ is supported by Astro 5, but 22 LTS is recommended) and npm. Run:

```bash
npm install
npm run check
npm run build
npm run dev
```

There is **no lockfile** in the supplied project; one is not fabricated here. After a successful installation, commit the genuine `package-lock.json` generated by npm to the repository. `npm run build` runs both `astro check` and `astro build`; output is the static `dist/` folder.

## GitHub → Cloudflare Pages

1. Create a **private or public GitHub repository** and upload the **contents of this extracted folder** to its root (not the parent folder). Commit the actual files; do not include `node_modules`, `dist`, `.env`, or private CV originals.
2. Cloudflare dashboard → **Workers & Pages** → **Create** → **Pages** → **Connect to Git** → choose this repository and production branch. (UI wording may differ.)
3. Build configuration: framework **Astro** (or custom static), **build command** `npm run build`, **build output directory** `dist`, **root directory** repository root. No Cloudflare adapter is needed for static output.
4. Set environment variable **`NODE_VERSION=22`** (Cloudflare build runtime setting). Set **`PUBLIC_SITE_INDEXABLE=false`** for all preview/branch deployments. Keep it `false` on the production deployment until the domain has been connected, the pages have been browser-tested and you explicitly approve indexing.
5. When launching on the approved domain, connect `husamyasen.com` using Cloudflare's domain setup and rebuild the production branch with **`PUBLIC_SITE_INDEXABLE=true`**. Preview deployments must continue using `false`. Cloudflare's environment variable configuration must keep staging and production values separate. **A build for public production must not simply reuse a preview build** because indexing controls are baked into static HTML at build time.
6. Verify `https://husamyasen.com/` redirects to `/ar/` and `/ar/`, `/en/`, `/pt/` and all other localized routes render. The root uses Astro's static `Astro.redirect('/ar/',302)` output; verify this behavior on Cloudflare before launch.
7. Verify production rendered `<meta name="robots" content="index,follow">`, `/robots.txt` with `Allow: /` and `/sitemap.xml` containing the 27 localized routes (not drafts). Preview builds use `noindex,nofollow`, `Disallow: /`, and an empty sitemap. Both environments use the intended `husamyasen.com` canonical URLs; **do not treat a preview canonical as proof of production deployment**.

**Important:** do not set `PUBLIC_SITE_INDEXABLE=true` for a public preview before launch. Do not add analytic IDs that have not been issued. No required secrets or API keys are used. Contact links are configured in `src/config/site.ts`.

## Writing articles (no CMS)

There is **no CMS dashboard**. Edit `src/content/insights/articles.json` and follow `src/content/insights/AUTHORING.md`. Add reviewed locale records and set `status: "published"` only for article pages ready to appear; drafts are excluded from links and generated routes. Real publication dates should be assigned on public launch, not invented from build time. Routes listed in `src/config/readyRoutes.ts` must correspond to implemented, public-ready pages.

## Before public launch

Run a real build and browser QA for all locales, responsive widths (360/390/768/1440), keyboard/mobile navigation, WhatsApp, print CV, SEO metadata, image crop and absent assets.
